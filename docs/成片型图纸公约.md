# 成片型图纸公约（正本）

> **射程**：一切分场景横切的剪辑/成片 structure 级图纸（旅拍、口播链、直播切片、Vlog 纪实……）。
> **性质**：写图纸时的公约与自检清单，**非运行时加载**——图纸必须自包含，本文是正本、图纸内是执行文本；
> 改公约 MUST 同批同步全部执行文本（登记表见 §五）。本文不进 npm 分发白名单（写作时约束，非客户交付物）。
> **立法**：主理人 2026-08-27 拍板（看板①「懒人模式」新定调，change add-production-skill-charter）。

## 一、模式公约（⟲ 2026-08-27 主理人拍板：按图纸类型分层）

命名统一：**快速成片**（弃名「懒人模式」「快速模式」）/ **逐步推进**。

- **通用型图纸**（场景横切：口播链、直播切片、通用解说、通用配音……）MUST 提供两种模式：
  **快速成片**（开工问询一次拍板 → 极少数结构化必停 → 一杆到底）+ **逐步推进**（每步停等确认）。
  两模式共用同一套规约与参数配方，**差别只在停几次，不在停不停**。
- **垂类示例图纸**（旅拍解说、美食解说、游戏解说……）承诺面**只有快速成片**：检查点一次拍板后
  一杆到底跑完交付；逐步推进不作为承诺面（增量重跑/悔棋通道照给，那是工艺能力不是模式）。
  **对垂类玩法本身不满意的出路 = 引导用户用 `gtrk-style-maker` 自建个性化 skill**——
  垂类图纸本来就是示例，演示链路怎么跑；真正个性化的项目工程归用户自建的 skill 持有，
  示例对它差着火候是定位使然，这句丑话 MUST 写进每张垂类图纸。

快速成片 ≠ 甩手掌柜。它不是让用户少参与，而是**参与时机全部前移**——低门槛带来的
「货不对板」失望感，根源都是某个本该用户拍的板被 agent 代拍了；把板前移，
跑完就没有可失望的悬念。一句话：**丑话说在前面，底层决策前置。**
（垂类单模式 MUST NOT 豁免决策前置三条腿——检查点照停、计费照在停点之后。）

## 一′、节奏信号识别：射程不限于图纸（⟲ 2026-09-04 立，由真机事故反推）

**模式承诺面**仍归 structure 级图纸（由 §一 界定：谁承诺「两种模式」）。
但**听懂用户喊停，是一切会自动接力的 skill 的共同义务，射程不限于图纸**——
**包括命令手册层**（那些自我定位「本 skill 是命令手册、不是图纸」因而不在 §一 射程内的
`gtrk-oralcut` / `gtrk-splitter` / `gtrk-matrix` / `gtrk-mg` 等）。

凡 SKILL.md 里写了「自动接力 / 顺势推进 / 别停下等用户 / 别停在交工」一类**默认推进指令**的
skill，MUST 同时写明：**用户表达节奏保留时 SHALL 停下等确认。**

**范围信号 vs 节奏信号 MUST 分别识别**（MUST NOT 只写范围侧的逃生门）：

| | 问的是 | 举例 |
|---|---|---|
| **范围信号** | **走多远**（我只要这一个产物） | 「只要这版剪辑工程」「先不往下」「暂不出片」「B-roll 就这样」 |
| **节奏信号** | **怎么走**（每步停等我） | **「逐步推进」**（§一 立法定名的正式模式名）、「一步步来」「先 X 然后我们再说」「我看看再定」「等我确认」 |

两者**语义正交**：用户完全可以「还要往下走（范围开着）」+「但每步等我（节奏要停）」。
只认范围的逃生门，恰好会在这种组合上失效。

★ **2026-09-04 真机事故形态**（本条款的由来）：主理人敲 `/gtrk-oralcut` 入场，指令是
「先智能剪口播 **然后我们逐步推进**」。当时 `gtrk-oralcut` 的逃生门只写了
「除非用户表示**只要这版剪辑工程**、暂不往下」——**纯范围条件**。用户说了「**然后**」，
明确表示还要往下 ⇒ 范围条件**逐字判定为不成立** ⇒ 硬默认「别停下等用户开口」胜出，
agent 同一轮内连跑 `/gtrk-splitter`、`/gtrk-ai-drama`、`/gtrk-mg`，
用户第一次开口已在几百条消息之后。**agent 对着那段文本执行是正确的，错的是文本。**

三条落地纪律：

1. **逃生门 SHALL 直接点名「逐步推进」**——那是本仓立法定名的词（§一 命名统一），
   用户就会照着这么说。一份只认范围信号的逃生门 = 违约。
2. **词表是护栏不是判据**：MUST NOT 写成「只认这几个词」。执行文本的写法应是
   「**用户表达节奏保留时停**」，上表只作举例——用户换个说法照样得听懂。
3. **停下时 SHALL 交代「下一步是什么、说一声就继续」**，使停等不退化成事事请示。

⚠️ **MUST NOT 因本条把默认改成事事停等**：没有节奏信号时仍 SHALL 自动接力——
那是快速成片的价值所在（§一）。本条只补「听得懂喊停」，**不改默认**：
无节奏信号的场景下，行为与本条落地前逐字一致。

## 二、决策前置三条腿

写图纸时逐个盘「agent 会替用户拍什么板」，每个点 MUST 归入三条腿之一，不许悬空：

1. **能前置的决策 → 开工问询一次拍板。**
   实例：口播链五问（多条形态 / 外录 / 文稿 / 几何 / B-roll 来源）、直播切片四问
   （时长几何 / 画面形态 / 贴片 / MG）、旅拍双场景识别。
   问询 MUST NOT 代猜（猜错代价大的点尤其如此），也 MUST NOT 碎问——一张表一次答完。
2. **开跑前不存在的决策 → 结构化必停。**
   停一次、清单式一次决策、不碎问。实例：直播切片选题清单（选题决策在跑之前不存在，
   前置不了）；旅拍/口播链检查点①（写完稿 / 粗剪完才有对象可拍板——稿件、画幅、音色、
   BGM、字幕样式一屏给齐）。**计费动作恒在停点之后**：未经确认 MUST NOT 发起计费。
3. **前置不了也停不住的（概率性 / 平台边界）→ 丑话说在前面 + 缺省不硬塞。**
   实例：直播切片贴片如实告知（告知不处置）、计费与实时价格转述、B-roll/MG 等可选增强
   缺省不铺不硬塞（问了/要了才做）、对轨低置信才请人工、字幕样式没选就 default 不追问、
   交付物边界先说清（粗剪工程 ≠ 成片）。

## 二′、质检三级：收敛前移（⟲ 2026-08-29 主理人拍板，**替代 2026-08-28 的「渲后 QC 铁则」**）

**改了什么**：渲后 QC 从「铁则强制」改为「**交付终检 · 用户可选**」，重铺职责移交**编排期**。
**为什么改**：4K AV1 实测渲染耗时过长，逼用户为质检渲一遍不成立——而质检的价值在于
**收敛发生在渲染之前**，全程只渲一次，替代原来的「渲 → 查 → 重铺 → 再渲」两轮环。

射程不变：凡成片含 B-roll / 素材铺排覆盖（解说链直排与软窗、配音链、旅拍/美食等垂类、
口播链 B-roll 增强）。纯口播无铺排、纯音频类产物无射程。

| 级 | 时机 | 查什么 | 强制性 | 成本 |
|---|---|---|---|---|
| **L1 结构自检** | 编排中（内建） | 切点/残片/最小槽/空洞；**候选无切点数据时前置声明「闪帧风险不可判」** | **恒开**（零成本，只看已有数据） | 零 |
| **L2 画音对齐** | 编排内、**落轨前** | 只查各 beat 的**卡点句**：画面有没有给到稿句说的东西；没给到就换候选重排 | 用户可选（`gtrk matrix lay --arrange-qc`），**按帧计费** | 每卡点句 1 帧/轮，轮数硬上限 2，零渲染 |
| **L3 渲后终检** | 交付渲那一次 | 爆音/封装/漂移等 VLM 不可见项 | **用户可选**（不再逼渲） | 一次渲染 |

落地口径：

- **L1 恒开**。它区分两件事：候选段的切点数据**缺省**（没扫过 ⇒ 闪帧风险**不可判**）与
  **空集**（扫过且确认无切点 ⇒ 可判且无风险）。**MUST NOT 把「不可判」说成「安全」，
  也 MUST NOT 说成「有问题」**——前者让风险留在暗处，后者让用户去修一个可能不存在的毛病。
- **L2 是花钱的动作**：跑前 MUST 报预估帧数并征求确认（`--yes` 跳过）；到轮数上限仍未修好
  MUST **交付 + 残余如实登记**，不硬卡（用户还要交片）不静默（他有权知道哪几句没对上）。
  拿不到卡点句时 MUST 明说「**跳过 ≠ 查过**」。
- **L3 不再强制**：本来就要本地渲交付时随渲附带（`gtrk render` 缺省质检 + `--no-qc` 逃生舱
  照旧），**不再为质检单独逼渲**。纯工程交付 / 云渲可用 `gtrk qc` 自行补一次。
- **凡跑过的质检，结论 MUST 随交付呈现**，一句人话分层：致命（纯黑/长静音/漂移）点名并给修法；
  已知良性形态（如引用段 ±pad 微片）如实登记不夸大。**MUST NOT 静默吞报告。**

> **口径迁移注记**：本节 2026-08-28 版要求「粗剪也不豁免、渲后必跑」。那条的动机
> （粗剪是用户调整成本最低的时点）依然成立，但**实现它的更好办法是 L1+L2 在落轨前跑完**，
> 而不是逼一次渲染。原文里「粗剪不豁免」的精神由 L1 恒开 + L2 可选承接。

## 二″、agent 视觉不可依赖原则（⟲ 2026-08-28 主理人拍板）

用户侧驱动 agent 的能力参差是常态，**凡需要「看画面」才能做的判断，MUST 产品化为同合云
原子并以文本形态产出**（镜头卡片/claims 判定/审计报告），图纸编排 MUST NOT 以「agent 具备
视觉」为前提。视觉分三层：T0 原生链=云端 VLM 看、agent 只读字（纯文本 agent 全链可跑）；
T1 加成层=有视觉的 agent 可额外拼版抽查（恒为可选增强）；降级路=云端不可用时退 describe
缓存的 desc 文本做文本级裁定（弱但可用，打可读 INFO）。已知边界如实登记：MG 颗粒观感
目前靠用户眼睛兜底（文本 agent 无法自检，属登记边界非欠账）。

## 三、MG 风格：内容驱动的临场泛化（正本，自口播链图纸 §六 迁此）

射程 = 所有含 MG 铺轨面的成片型图纸：

- **有栏目风格 skill** → 走栏目（经栏目配置注入），本节不适用。
- **没有** → 按**当下这片的内容**现场泛化一套自洽风格直接用：
  1. 内容调性 → 风格基调：讲什么（严肃知识 / 情感陪伴 / 轻快种草）→ 配色倾向、字体气质、
     动效克制度（知识类稳、情绪类柔、种草类快）；
  2. 基调定了**全片贯彻**：同片所有颗粒同一套色板与字体气质，MUST NOT 逐颗粒各自为政；
  3. **两个 MUST NOT**：不把某套固定「通用默认风格」死板套所有片子（换了形态的强行锚定）；
     不因无栏目 skill 放弃风格一致性（那是没有风格）。
- 一句话：**风格必须有，但不强行锚定**——锚在这一片的内容上，而非某个预设模板上。

（spec 条款住 talking-head-skill capability「MG 风格采用内容驱动的临场泛化」；旅拍 §六
「因势象形」是其垂类实例。）

## 三′、BGM 选曲：同样是内容驱动的临场泛化（⟲ 2026-08-28 主理人挑刺定案）

**症状**：美食/旅拍无论什么题材都来回那几首。**根因不在检索算法**（换检索词就换一批曲，实测
「市井烟火轻快」与「深夜孤独钢琴」返回两组完全不同的结果），在编排纪律——套路化检索词 +
拿 top1 就用 + 跨片零记忆。三条对策：

1. **检索词内容驱动，禁通用词**：BGM 检索词 MUST 从**这一片的具体内容**生成（情绪弧 / 地域
   文化 / 节奏器乐三组维度），且**至少含一个只有这一片才成立的词**。「温暖 治愈 轻快 日常
   烟火」这类放之四海皆准的词对任何片子都成立 = 等于没写（三家日本小店套同一组词就是这么
   撞的曲）。与 §三 MG 风格同一原则：**锚在这一片的内容上，而非某个预设模板上**。
2. **候选给用户挑，MUST NOT 默认 top1**：`--top-k 5 --diversity` 取候选，附试听链接
   （`download_url`）并**说明各候选的气质差异**，进检查点①一屏拍板。试听链接缺席 = 推荐未完成。
3. **跨片避让走机制不靠记性**：`gtrk audio lay` 落轨即记账（`~/.gitruck/bgm-history.json`），
   `matrix material --scope audio` 缺省避让近期用过的曲子（`--exclude-recent <n>` 调窗、
   `--no-exclude-recent` 关）。伴奏版与原曲归一为同一首，换个版本不算换曲。
   曲库小到全被避让时回退原结果并明示——**宁可少滤不可滤空**。

## 二‴、质量信号依赖链：免索引 = 降档，不是「快一点」（⟲ 2026-08-28 主理人拍板）

射程 = 一切消费本地素材铺轨的成片型图纸。**素材索引不是「快慢」的优化项，是质量信号的载体**：

| 信号 | 载体 | 缺了会怎样 |
|---|---|---|
| `mark` 美观度 / `highlight` 看点 | 检索 plan → `matrix describe --plan` 注入 | 权重传了也全部中性，原样回吐给语义分 |
| `blurry` 模糊降权 | 同上（随 describe 注入） | 糊帧与清晰帧同权 |
| `motion` 高运动降权 | 索引产出的段级字段 | 抖/摇段不降权 |
| `cuts` 端点残片收缩 | 同上 | **闪帧的机制性根因** |

★ **高档直排（`beat.arrange_mode: "direct"`）改变了最后一行的性质，但没有取消它。**
直排槽照样过同一套窗口精修，于是「我要这一段」与「这一段不闪帧」不再是二选一。
但精修拆成两步，两步**各自依赖不同的东西**，缺席后果也不同：

| 精修子步骤 | 依赖 | 缺席时 | 位移量级 |
|---|---|---|---|
| 端点残片收缩（切点吸附） | 段级 `cuts`（**要素材已索引**） | 整步无数据可用 | ≤1 秒 |
| 帧网格吸附 | 素材**帧率**（全 plan 任一 beat 见过这条素材即可，**不要索引**） | 整步不生效，端点留在非整帧 | ≤半帧 |

两条是**独立**的边界，MUST NOT 混为一谈——混了会让「只缺切点」的槽白白丢掉帧吸附。
回执分别以 `has_cuts` 与 `fps`（`null` = 查不到）如实报，`cut_snap` 三态再把
「引用段按你的标注主动不吸」与「素材没索引想吸也无从吸」分开。

所以直排档下的正确说法是：**未索引 ⇒ 只得部分收益**，MUST NOT 表述成
「直排 + 高档就一定不闪帧」。

手写 plan（免索引直排）把这五条一并断掉。260828 三条美食片实测 `describes` 行数为 0——
`--mark-weight 0.3` 明明传了、一分没参与，而闪帧要靠两轮「QC→反算→重铺」才勉强收敛。

三条纪律：

1. **索引前置**：快速成片编排第①步即起（未提速期与写稿/TTS/检查点①**并行**，不串行干等）；
2. **免索引路径 MUST 明示代价**：告知上表五条信号失效与闪帧风险，**MUST NOT** 表述成
   「快一点」——它是质量档位下降；用户坚持则照办，并在交付说明里如实登记走的是降档路径；
3. **权重开了要验证生效**：`matrix lay` 在「开了权重但本片零缓存覆盖」时打告警，
   看到即说明 `describe --plan` 那步漏了或没生效，MUST NOT 当噪声忽略。

## 三″、平台库检索：通用成片缺省实拍向（⟲ 2026-08-28 主理人提醒）

平台素材库的 `material_class` 分 `real_shot`（实拍）与 `concept`（概念/意象）两档
（**仅矩阵成员口存在**，公开口无此字段）。口径：

- **通用成片流程缺省走实拍向**（解说链、配音链、旅拍/美食等垂类、口播链 B-roll 增强）：
  这些片子的画面在描述**具体发生过的事**，概念意象镜头接进去是气质错配。检索时显式
  `--material-class real_shot`（成员口生效，非成员口自动忽略不报错）。
- **概念素材只在栏目调性 match 时启用**：栏目本身讲抽象命题（如《实在界漫游指南》这类
  心理学/人文社科栏目）才用 `concept`，且落在**栏目配置** `broll.material_class_policy`
  里由栏目持有——MUST NOT 在通用图纸里写死某一档。
- 解说链另有更严的上位条款：**主体画面只用本地素材**（素材就是被讲的对象本身），
  平台库最多补空镜作辅料、缺省不掺；本节口径作用于「确实要用平台库」的那一小部分。

## 三‴、第三方 skill 推荐面：三档、克制、不点名（⟲ 2026-09-10 主理人拍板，change add-third-party-skill-catalog）

外面有一批高 star、许可干净、产物能落进我方车道的第三方 skill（开场钩子、复杂 MG 演绎、字体动效、数据动画、AI 再现分镜、拼贴外包、字幕动效……）。
**集成形态 = 推荐，不打包**：框架只持一份随包推荐目录（`src/data/third-party-skill-catalog.json`，`gtrk skills recommend` 查），装不装是用户自己的行为，
装了用 `gtrk skills add <owner/repo> --produces <车道>` 登记进栏目配置 `style.skills`，之后各车道驱动器按 `produces` 就能解析到它。

**推荐面三档**（射程 = 全部成片型图纸的开工问答收口处）：

1. **轻提（恒有，一句）**：开工问答收口时多问一句「要不要看看第三方 skill？」，**不列名**。
2. **定向推（条件触发，多 1–2 句）**：只当用户原话或稿件**命中目录场景触发词**（`scenes[].triggers`，数据在目录里、本文不复制）时，
   在①之上点名 **≤ 2 个**（`gtrk skills recommend --scene <id> --json` 取 tier 最高者）并各给一句为什么。
3. **展开（用户感兴趣或追问才有）**：再给完整块——用途 / 安装命令 / 许可与依赖提示 / 登记命令（即 `recommend` 的人读输出）。

**纪律**：①②合计 MUST NOT 超过三句；MUST NOT 要交互确认、MUST NOT 打断动线；同场景同会话只推一次；用户答「不要」后零动作不再提。
**图纸正文 MUST NOT 硬编任何第三方仓名或安装命令**——仓名 / 许可 / 命令全住目录，目录随发版刷新，图纸只写「查推荐目录」。
推荐文案一律带「star 与许可以仓库页为准」；全链路型 skill（自带配音 / 音乐 / 字幕）只作「整段外包」推荐并提示回轨只取画面。

（spec 条款住 `third-party-skill-catalog` capability「图纸层推荐面 SHALL 分三档且克制」；各图纸落点见 §五 附表。）

## 三⁗、前六秒：钩子层（⟲ 2026-09-10 主理人拍板 Q6，change add-blueprint-opening-hook-layer）

**射程**：稿件可控的两条通用型图纸——口播链（`gtrk-talking-head`）与配音链（`gtrk-voiceover`）。解说链家族的开场由看点前置与 rubric 承接，不在本节；vlog-docu 搁置中不动。
前六秒决定完播，而外部钩子 skill 全是纯文本、不知道我方四车道；「钩子文案 + 前六秒画面 + 字卡节奏」三合一由图纸自持。

**产出物「前六秒方案」**（检查点①前由 agent 产、随其他拍板项**一次拍板**；MUST NOT 单独追问、MUST NOT 在检查点①之后再出现）：

1. **钩子文案三候选**：五型任选（**悬念 / 反差 / 利益 / 痛点 / 故事**），每条 **15–30 字**、口语、无违禁词、与正文首段自然衔接。
   口播链基于毛片转写首段改写，配音链基于稿件首段改写；**只改开口方式，MUST NOT 改动用户的事实、数据与结论**。
2. **画面层建议**：前六秒主层 **A_ROLL / MG 字卡 / 拼贴或 AI 片段** 三选一。拍板后作为开场 beat 的 lane 输入进拆分派单：
   选 MG 字卡 ⇒ 拆分稿开场 beat 的 MG 派单 `handoff` 写 `theme: opening-hook` 并带拍板的屏字；选拼贴或 AI 片段 ⇒ 开场进 AI_DRAMA 队列；选 A_ROLL ⇒ 开场不派辅助层。
3. **字卡节奏**：屏字 **≤ 8 字**、首字出现 **≤ 1 s**、与口播句同步落幕。MG 车道产能由栏目 skill 或中性块承接，本节不产颗粒。

**纪律**：缺省不硬塞（§四）——用户答「开场照原样」= 零动作，后续不再提；文风铁律照继承（正本在 gtrk-travel-recap §三通用框架层，含「杜绝否定—转折对举」）；
先给自持方案，**再**一句轻提「要更多变体也可以看第三方钩子 skill」（走 §三‴ 的 `hook` 场景，不列名，MUST NOT 以第三方替代自持方案）。

**五型各一例（通用题材，MUST NOT 用某一栏目的专属假设）**：

| 型 | 正例（≤30 字） | 反例（为什么不行） |
|---|---|---|
| 悬念 | 「去年营收翻三倍，靠的是一个我差点砍掉的功能。」 | 「你绝对想不到……」（空悬念，无信息） |
| 反差 | 「团队只有三个人，客户名单比对手长一倍。」 | 「不是我们厉害，而是对手太弱。」（否定—转折对举） |
| 利益 | 「看完这三分钟，你能省下一整周的剪辑时间。」 | 「这个视频对你很有用。」（利益不具体） |
| 痛点 | 「剪一条口播花四小时，多半耗在废话上。」 | 「剪辑真的很烦。」（无场景无数字） |
| 故事 | 「上周三凌晨两点，我收到了第一封付费邮件。」 | 「今天讲讲我的创业故事。」（预告式，不进场景） |

（spec 条款住 `opening-hook-layer` capability；两张图纸的执行文本落点见 §五 附表。改字数 / 秒数口径只改本节，图纸引用不复制。）

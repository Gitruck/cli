# gtrk-travel-recap（旅拍解说 · 组合成片图纸）

把**一个旅拍素材文件夹**变成**一条中文解说成片工程**：理解素材 → 三段式写稿 → 检查点①一次拍板 → 配音/建工程/拆分/B-roll/字卡/BGM/字幕 全自动 → 客户端出片。

> **定位**：本 skill 是第一张 **structure 级组合图纸**——它不新增任何命令，只编排既有原子零件（transcript / matrix / project init / split / mg / audio lay / subtitle lay / TTS 工具）。零件的参数细节以各自 skill（`gtrk-matrix` / `gtrk-splitter` / `gtrk-mg` / `gtrk-transcript`）与 `--help` 为准，**本图纸引用不复制**；但**编排次序、检查点、配方级参数**以本图纸为准。**CLI 是手，你是脑**：写稿、切 beat、挑候选信号、产字卡颗粒、管检查点，都是你的活。
>
> **家族归位（2026-08-27 主理人拍板）**：本图纸是**解说链**（`gtrk-narration` 正本）的先行垂类实例——解说 = 把素材语料自带的叙事时序提炼看点后重述；时序铺排三档、引用段、出处对齐等链级条款以 `gtrk-narration` 为正本，本图纸的旅拍要素层（贵大奇多钩子/攻略 tips/升华笔法）为垂类专属。素材无自带时序的题材（科普/情感/带货）属配音链，走 `gtrk-voiceover`。
>
> **本 skill 已含跑通全链需要的全部编排信息**。打样验证：2026-08-19 黄石公园 20 分钟长视频二创，双轮真机全链通过。

## 一、输入契约与双场景识别

用户给**一个素材文件夹**（或多个，逗号分隔传 `--dirs`）：

| 内容 | 必须性 | 说明 |
|---|---|---|
| 视频/图片素材 | **必须** | 一条长视频（二创）或一堆素材（原创拍摄）皆可；图片会被自动运镜成动态上轨 |
| BGM 音频文件 | 可选 | 没有就走素材矩阵搜索（见检查点①） |
| 介绍类文本（txt/md） | 可选 | 有则作写稿补充素材 |

**一夹多片时检索域按场景分流（★ 2026-09-02 补）**：二创场景一个夹里常躺着好几条互不相干的片，
**B-roll 检索域 MUST 收窄到正在做的那一部片本身**——`--dirs` 既吃文件夹也吃**单个素材文件**，传文件即把域收窄到该素材（见 §五 ⑦ 的★铁则）。
原创（自拍素材集）那一档整夹就是这一片的素材域，**传夹正确**。

**MUST NOT 下载二创源片 / 主体素材**：网络视频二创场景下，下载动作归用户（版权责任边界）——用户给的文件夹里是什么就用什么。**射程只到源片与构成成片主体画面的素材**：平台授权素材（同和素材矩阵的 BGM / 空镜）的**签名直链不在此列**（⟲ 2026-09-02 收窄：原措辞写「任何网络下载」，严于本 skill 自己的规格，且让 §四.4 那步 BGM 落地在字面上不合法；家族口径见 `gtrk-narration` / `gtrk-food-recap`——那两份长期同时挂着同款禁令与「`song` MUST 下载 `accompaniment_url` 伴奏版」，并存即证禁令从来只指源片）。收窄 MUST NOT 被读作给源片下载开口子——那条版权边界一字不动。

**双场景识别**（决定理解编排走法）：
- **二创**：文件夹里是网络旅行长视频（通常含博主解说语音）→ 原片文案是写稿主料；
- **原创**：用户自己拍的素材集（通常无解说语音）→ 素材理解（describe）是写稿主料。
- 拿不准就 ffprobe 看时长与条数：单条 10 分钟以上大概率二创；几十条短素材大概率原创。仍拿不准，问用户一句。
- 原创场景的素材集常常**通篇没有对白**——那就不跑转写，下表的语种一问以「无对白 / 不转写」闭合，MUST NOT 因缺这个答案阻塞开工。

**开工三问：稿源 · 声音基座 · 源片语种**（⟲ 2026-08-27 解说链家族回炉先立稿源与声音基座；⟲ 2026-09-02 补语种这一问——260902 真机一条**粤语对白**的片子按缺省 `zh-CN` 静默转写跑完，全链无一处问过语种。三问开工时与双场景识别**一并问清、一张表一次问完、MUST NOT 代猜**）：

| 问 | 选项与走法 |
|---|---|
| 稿从哪来 | **AI 代写**（缺省，§三 规约写）/ **用户自备稿**——跳过写稿，稿直接进检查点①过目（文风铁律不强加于用户手稿，只提示明显硬伤） |
| 声音怎么来 | **TTS 配音**（缺省，检查点①挑音色）/ **用户自己念**——拿念稿毛片先走 `gtrk oralcut` 粗剪（带稿最准；外录收音先 `gtrk audio align` 对轨），产出的粗剪工程即时间基座，§五 的「配音④→建工程⑤」两步跳过，从拆分⑥接入，后续铺排/字卡/BGM/字幕照旧 |
| **源片语种 / 方言** | 取证=**听一段 / 看片内有无内嵌字幕 / 看素材出处**；答案定 §五 ① 的 `gtrk transcript --lang`（`zh-CN` 普通话 / **`zh-HK` 粤语** / `en-US` / `ja-JP`…）。**MUST 问用户、MUST NOT 代猜、MUST NOT 以缺省 `zh-CN` 静默开跑转写**——转写是计费动作**且早于检查点①**：**非中文素材**（`en-US` / `ja-JP`…）语种传错，用户在检查点①拿到的稿子就是坏的、重来要再付一次 ASR（真机实证）。**中文这一档（`zh-CN` ↔ `zh-HK`）不在此列**：粤语 **SHOULD** 如实填 `zh-HK`（元数据诚实 + 备将来链路切换），但当前实现下该参数**对粤语无影响**——两种写法发出的请求逐字段相同，详见 §五 ① 注。素材无对白：答「无对白 / 不转写」即闭合 |

## 一′、素材适配闸（写稿前必过 · ★ 2026-09-02 真机事故立）

> **事故形态**：三条素材里有一条是**有剧情、有台词、有摆拍的学生短片**，本图纸从头到尾跑完（含 TTS 计费步骤）、**零提示**。
> 根因不是漏写一句，是**唯一的路由条款判的是「时序」而不是「题材」**——§一 的家族归位按「素材有无自带时序」出链，
> 而剧情短片**自带叙事时序**（剧情线），按解说链判据它不但不出链，**反而正落在射程内**，出链闸永远不会触发。
> ⇒ **本闸判的是题材，与「有无自带时序」正交，MUST NOT 由后者代行。**

**取证零新增计费**（读的都是编排里本来就要产的东西，MUST NOT 为这道闸新加一次 describe 或转写）：

- **原创场景**：读 `gtrk matrix index` / `gtrk matrix describe` 已产的 `desc`（中文视觉描述）与 `tags`；
- **二创场景**：读 `gtrk transcript` 全文。

**判据（可判定，逐条素材过一遍）**：

- 主判据——这一条**能不能回答「这是在哪、看到了什么」**（可辨认的地点 + 所见之物）。能答的占比过低 ⇒ 不适配；
- 反向命中任一即不适配：文本呈现**剧情对白**（人物一来一往推进情节）/ **摆拍表演**（演出来的而非记录下来的）/ **单一室内场景**（全片不出一个可辨认的地点）。

**命中即硬停：MUST NOT 进入写稿**（形制照 `gtrk-vlog-docu` 的立神闸「写不出来 = 神没立住，MUST NOT 进入写稿」）。
硬停位置是**写稿之前 = TTS 计费之前**——它与 §四 检查点①「未经确认 MUST NOT 发起计费动作」是同一条防线的**前置一层**：
检查点①拦的是「稿子对不对」，本闸拦的是「**这活该不该接**」。停下时 MUST 如实列出**哪几条不适配 + 依据原文**
（引 `desc` / `tags` / 转写里的原句，别只下结论），并给三条出路：

| 出路 | 怎么走 |
|---|---|
| ① **剔除** | 把不适配的那几条摘出去，用剩下的素材继续跑本图纸 |
| ② **改投** | 剧情 / 影视 / 游戏这类有时序但非旅拍的题材走 `gtrk-narration`（解说链正本）；素材无自带时序的题材（科普/情感/带货）走 `gtrk-voiceover` |
| ③ **照跑** | 用户坚持就照办，但 **MUST 在交付说明里如实登记**「素材与旅拍垂类不匹配、要素层（贵大奇多钩子 / 攻略 tips）多半落空」（降档路径如实登记，口径同《成片型图纸公约》） |

**两条边界写死**：agent **MUST NOT 自行判死**（决定权在用户，本闸只提名不宣判）、**MUST NOT 静默照跑**——
后者正是 260902 那次事故的形态：全链跑完、零提示、钱已经花了。

## 三、三段式写稿规约

### 通用框架层（可移植——其他垂类图纸原样复用本层）

**结构三段式**：第一部分「钩子」抓眼球保留存 → 第二部分「干货」给内容价值 → 第三部分「升华」给情绪价值。爆款四属性贯穿：快乐+知识+共鸣+节奏。

**背景检索建议（⟲ 2026-08-28 主理人拍板）**：写稿信息源除了画面与音频（字幕不一定有），
**建议**执行 agent 对素材主题的关键词做一轮背景/上下文检索（地名典故、店家来历、片名与
公开报道等），检索所得须与素材内可见事实互证后才可入稿、并在拍板档案里标注来源。
有检索能力就做、没有不强求（能力缺席按纯素材信息写，不算违约）；检索到的**外部数字与
争议性说法宁缺勿滥**。

**文风铁律**：
- 禁模板连接词：让我们/首先/然后/最后/此外 等一律不用；
- 拒翻译腔：全部短句中文语感，无欧化从句；
- **禁「否定—转折」对举句式（★ 主理人 2026-08-19 拍板，最高优先级）**：**八成的 AI 厌恶感来自这一种句式**。禁的是整个家族，不只字面：
  - 「这不是 X，而是 Y」／「与其说是 X，不如说是 Y」
  - 「X 不仅仅是 Y，更是 Z」／「X 不只是 Y，它还是 Z」
  - 「重要的不是 X，而是 Y」／「真正的 X 从来不是 Y」
  - 「不是因为 X，而是因为 Y」／「X 靠的不是 Y，是 Z」
  - **识别特征**：先立一个没人主张过的靶子再推翻它、用对偶结构制造顿悟感、句子的信息量全在后半句而前半句只是垫脚。
  - **改法**：把后半句直接说出来，删掉前面那个假靶子。「这不是一条水渠，而是一条生命线」→「几百个村民用铁锤在悬崖上凿了三年，就为这一条水渠」。**能直接陈述的事实，绝不用对举包装**。
  - 这条也适用于标题与 HashTag。
- **禁幼稚拟声与过度儿化**（★ 打样校准）：「轰隆隆砸下来」这类拟声，换成**真实事实**（「从九十多米高处坠进谷底，比尼亚加拉还高出近一倍」）——数字与事实比拟声词有力得多；
- **风格目标 = 与原素材旗鼓相当**：原片多吸引人，解说就得配得上——贴着原片气质走，**不加分**（加分是业务化的事，走栏目风格）**不减分**。

**成片时长 = min(内容所支撑, 素材所支撑)**：
- 内容支撑：有多少真东西说多少话，素材再多也不注水；
- 素材支撑：按「30% 图片×8 秒 + 70% 视频素材时长」估算上限，稿子在写稿阶段就按上限收敛（不要等铺轨时开天窗）；把这个秒数换算成字数用下一条的折算口径（**公式本身不动**）；
- **折算口径 = 挂钟语速**（wall-clock：稿件字数 ÷ 合成音频总时长，**含**句间停顿），**按检查点①选定的那条音色取值**；取不到该音色的语速就用**缺省 ≈330 字/分钟**，并明说这是缺省估值、**不是该音色的实测值**。3 分钟成片 ≈ **1000 字**。
  缺省 330 的出处（★ 2026-09-02 立，`fix-speech-rate-calibration`）：全库 49 条 zh-CN 音色挂钟中位 308.7、`narrator` 349.3（**单点实测，未覆盖全库**）、260902 真机三条片 316–342 —— 逐条档案与标定方法见 `references/speech-rate.md`，**MUST NOT 把那张表贴回本图纸**（单一真值源，垂类只许引用）。
- ⚠️ **MUST NOT 拿计费折算常量（240 字/分钟）推稿子字数**：那是**计费**用的保守下界（volc 单点实测 260 再下调留余量），与写稿侧的保守方向**正好相反**——计费侧低估语速只是「分钟数变大、不少收」，写稿侧低估语速却会让稿子写短、成片缩水（按 240 写 3 分钟 = 720 字，用 349 的挂钟语速实播只有 2.06 分钟，**缩水 31%**）。计费那一栏见 §九，两个数 MUST NOT 互相冒充。

**写后自校验清单**（逐项过，不过重写）：
- [ ] 三段结构完整、时长在 min 公式内
- [ ] 禁词零命中、无翻译腔、无幼稚拟声
- [ ] **「否定—转折」对举句式零命中**（逐句扫「不是…而是」「不仅…更是」「与其…不如」及其变体；含标题与 HashTag）
- [ ] **重复字/错字扫描**（★ 打样实锤：「下瀑布瀑布」重复字 TTS 会照念）
- [ ] 事实矫正：转写稿的明显错误（如数量级离谱的数字）按常识矫正或模糊处理，不确定的不引用
- [ ] 解说序 ≈ 素材序（二创场景：按原片游览顺序写，B-roll 时间窗天然可用）
- [ ] 同批产出：标题 3-5 个（≤30 字）+ HashTag 3-5 个

### 旅拍要素层（垂类专属）

- **钩子要素**（第一部分重点找）：贵大奇多 / 热门 IP / 名人名著 / 知名历史事件 / 全球 TOP 榜 / 奇闻轶事 / 脍炙人口；
- **干货要素**（第二部分）：攻略 tips / 游览流程 / 干货&经验 / 旅途见闻，幽默口吻、隔几句一个梗（谐音/反转/无厘头），在精不在多；
- **升华笔法**（第三部分）：思考/感悟/启发/感动，正能量收束；第一人称历数、物象隐喻收尾都是成熟笔法；
- 有文化衍生空间（历史典故/风俗人文）可适当发挥，但以原素材内容为锚。

## 三′、L1 看点 rubric · 画面投影版（260828 新增，供 `--highlight-weight` 用）

`highlight` 是**镜头看点分**——服务端 VLM 对着一帧画面打 0–100。旅拍这一档的准则
（`highlight_rubric`）：

```
判这一帧对旅拍短视频有没有「看点」，0-100：
- 奇观地貌：雅丹/冰川/星空/沙漠/峡谷等罕见地形
- 极端天候光线：日出日落、逆光、雪雾、暴雨、极光
- 人文场面密度：市集、节庆、宗教仪式、当地人劳作
- 反差罕见：人与巨大景观的比例、无人区里的人造物、动物
- 规模感：能看出「有多大/有多高/有多远」的构图
```

**配方级参数口径**（打样标定）：
- `--mark-weight 0.3`：美观度加权起步值（mark 缺失素材中性不受罚）；
- `--highlight-weight 0.2`（260828 新增）：看点加权，配 §三′ 的 rubric。与 mark 正交——
  mark 判「好不好看」、highlight 判「有没有看点」。两权之和 0.5，语义仍占一半，
  **MUST NOT 加到语义压不住**（那会变成「专挑好看的，不管说的是什么」）。
  ⚠️ 两个权重与 blurry 降权**都依赖 `matrix describe --plan` 跑过**（编排 ⑦ 那一步）；
  没跑就是全部候选中性、排序与不开权重逐字节一致——lay 会就此打告警，看到就说明漏了；
- `--gap-fill fast`（★ 主理人 2026-08-21 拍板：快速成片不留空）：主轨空洞按**五级**依次填——放宽地板取剩余候选 → 段界内延长相邻颗粒 → **跨 beat 借未消费候选** → **次地板补真画面** → 仍不够才落黑片。⚠️ 后两级容易被误当 bug：借来的画面**与本段稿子相关性弱**，次地板槽是**不到 1.2s 的快切**；两者都会在日志里指名报出（`kind` 为 `borrowed` / `subfloor`）——那是**如实告知，不是缺陷，别当 bug 上报**。宁可这样也不落黑，是因为客户端主轨磁吸开启时 gap 会被吸除、画面与配音错位，快速成片以画面连续性优先；CLI 缺省是 solid（黑片垫齐，精修可见），本配方须**显式传 fast**；
- 句界吸附（`--cut-align`）默认 0.7 即三七开拍板值，不用传——约七成字幕句起点恰逢镜头切点、三成有意错开；
- **BGM 音量口径 = -20dB（线性 0.10，★ 主理人 2026-08-19 拍板定值）**：配音主导原则——BGM 是垫底不是主角，成品音乐响度天然高于 TTS 电平。⚠️ 契约 volume 字段**只写线性增益、MUST NOT 写 dB**（composition-contract-v1 §4 明文，dB 残档曾致客户端打不开工程）——-20dB 换算=10^(-20/20)=0.10 写入。**客户端音量面板显示的就是 dB 值（标准 20·log10 换算，两侧同一标尺）**：写 0.10 打开面板即显示 -20.0，主理人实测该值听感最佳且偏保守（宁小声不大声）。用户嫌低在客户端拉高（终调权在客户端）；
- 时间窗（`--source-window`）：二创场景解说序≈素材序时按 beat 对应的原片区间约束检索（可选增强，全库检索在几百场景规模下命中率已够）；
- 素材不二用、黑片叠底、层序（黑底最低号<common<concept<local，契约=大号在上）均由 lay 内建，MUST NOT 绕过。

## 六、MG 轻量字卡规约（旅拍向最小集，不建栏目 skill）

> ⟲ 2026-08-27 注：本节「因势象形、不建栏目 skill」是**成片型图纸通用原则「MG 风格 = 内容驱动的临场泛化」的旅拍实例**——风格必须有，但不强行锚定（锚在这一片的内容上，而非预设模板）。原则正本在仓内《成片型图纸公约》§三（`docs/成片型图纸公约.md`），后续新图纸引用正本。

快速成片**禁留白**（★ 打样修正）——字卡按下述规约**先斩后奏**直接产好叠上，用户不满意在客户端删，别等确认。

- **内容**：地名字卡为主（地标名中文+英文/头衔副标），可加里程/价格数字卡；每片 2-4 颗、挂在地标出场句（拆分稿 aux_layers overlay）；
- **形态**：左下安全区地名条——竖色条装饰+半透明深色衬底圆角条+主标题（60px 级粗体白字）+副标题（28px 级 75% 白）；透明叠加不挡画面主体；
- **动效**：入场滑入淡入约 1.5-2s → **定格驻留到坑位末尾**（gsap-emit v1 铁律⑦：时间线总长≥坑位+0.3s，禁全局渐隐）；
- **工艺**：严格按 `contracts/gsap-emit-v1.md` 颗粒骨架（`<template>` 包裹/1920×1080/`gsap.timeline({paused:true})`/`__timelines` 注册/无随机无时钟/lib.baomitu.com GSAP CDN）；字体用渲染字体注册表在册族（如 `Alibaba PuHuiTi`）；实心衬底写子层不写根（铁律 4）；
- **产前抽帧**（overlay 必做）：对挂点用本地 ffmpeg 抽 1 帧看底轨明暗与主体位置（临时文件落系统 temp 用完即删）；
- 产物存 `<工程目录>/mg/<composition_id>.html`，逐颗 lint 过了再铺。

**字卡自检清单**（★ 2026-09-02 补，形制同 §三「写后自校验清单」）：

- [ ] 拆分稿写完，**数一遍** `aux_layers` 里 `type:"overlay"` 的条数，是否落在**每片 2-4 颗**；
- [ ] 落地后核对 `gtrk split --json` 的 `queues.mg` 条数，与上一条对得上、且仍在 2-4；
- [ ] 不足按地标出场句补挂；超出按「稀缺才有力」裁掉。

> **为什么补在图纸而不上机器闸**（拍板留痕）：「2-4 颗」以前**全链无一处拿它比对**——`split` 只如实报数、
> `mg` 的 `empty_queue` 只防误清空整轨、`mg lint` 是单颗 HTML 内的静态校验、`splitdoc` 对 `aux_layers`
> 条数零校验；于是真机两条片各只落 **1 颗**，下游每一环都 100% 报「全部铺成」，观感上完全正常，**无人喊**。
> 但它与仓内唯一那道数量硬闸（`MAX_ANCHORS_PER_BEAT`）**判据类型不同**：那条的理由是**工程后果**
> （锚过密会把序贯填充区间切碎），字卡颗数是**审美编排量**——上通用闸等于让通用契约背垂类配方
> （撞 `gtrk-mg`「不硬编任何栏目的视觉风格」）。缺口的真正位置是**图纸缺自检项**（§三 有、§六 没有），
> 补在缺口上最省，**零代码变更**。⚠️ 反方也如实记：颗数是 `dispatch.mg.length` 一行就能算的机器可判量，
> 若这类漂移反复发生，改上「通用可选入参 + 由图纸传值 + 非致命告警」是正当的。

## 改工程：走 `gtrk patch`，不要裸手改 JSON

跑完之后要**微调某个片段**（挪位置 / 改时长 / 切开 / 改音量）时，一律用 `gtrk patch`：

```bash
gtrk patch move --project <dir> --clip <clip_id> --to 5.0
gtrk patch trim --project <dir> --clip <clip_id> --out -1s
```

**MUST NOT 直接编辑 `.gtrk` 的 JSON。** 片段时码是两套并存的（`clip_st`+`clip_ed` 与
`clip_st`+`duration`）：改一份不改另一份，客户端优先读 `clip_ed`、后端又不强校验它 ⇒
**没人报错，成片却用了陈旧出点**。`gtrk patch` 替你做恒等式同步 + 帧对齐 + 写前全档校验。

> 参数手册在 `AGENT.md` 的「元素级编辑：`gtrk patch`」一节与 README 命令参考。
> 本节**只指路不搬手册** —— 搬过来就会长出会漂移的副本。
